# Lib.Db AOT/TVP Risk Ledger

This is an internal maintainer risk ledger, not consumer API documentation. It may mention internal verification, benchmark, coverage, database harness, or release-process details that are intentionally excluded from consumer skills and public usage docs.

Scope: runtime-first TVP binding, static-shape AOT fast path, schema/cache flush, and benchmark artifacts.

Status terms: `Mitigated`, `Open`, `Accepted`, `Needs owner confirmation`.

| Risk | Threat | Current control | Residual action | Status |
|---|---|---|---|---|
| Identifier injection / `TvpTypeName.Parse` | Attacker-controlled TVP type names could append SQL tokens or redirect binding to an unexpected schema/type. | Runtime TVP entry points normalize type names through `TvpTypeName.Parse`; invalid identifiers fail before SQL execution. Schema lookup SQL must parameterize schema/type filters. | Keep unit coverage for semicolons, brackets, empty parts, three-part names, and whitespace. | Mitigated |
| Raw SQL / value injection | TVP rows or scalar values could be concatenated into SQL text by callers. | TVP rows and scalar values are provider parameters; README examples pass scalar + TVP values through parameter objects. Raw SQL policy remains a guardrail, not a security boundary. | Security docs must keep directing production apps to DB permissions and parameterization. | Mitigated |
| Secret exposure | Connection strings, passwords, tokens, or benchmark env vars could leak into logs or reports. | Benchmark setup reads `ConnectionStrings:Benchmark` / `LIBDB_BENCHMARK_CONNECTION` but does not print values. Final reports should summarize key presence only. | Keep command output redacted in CI and local notes. | Mitigated |
| Benchmark artifacts | BenchmarkDotNet reports can capture environment variables, command lines, or copied appsettings. | `Verification/projects/Lib.Db.Benchmarks/ScanBenchmarkArtifacts.ps1` scans artifact text files under `Verification/artifacts/benchmarks` for connection-string/password/token patterns and prints paths only. | Run the scan before commit/release and inspect any flagged path locally without sharing secret values. | Mitigated |
| Local benchmark encryption | Local/direct SQL Server benchmarks can normalize insecure connection-string habits such as disabled encryption or trusted certificates. | README instructs local benchmark connection setup without printing values. Project rules limit benchmark DDL to C#/benchmark app paths. | Prefer encrypted local connections when supported; any dev-only trust exception must stay local and out of committed config. | Accepted |
| Memory-optimized TVP opt-in | Memory-optimized TVP coverage requires durable database metadata changes, including a `MEMORY_OPTIMIZED_DATA` filegroup/file container and `AUTO_CLOSE OFF`. | The opt-in setup SQL is restricted to `LIBDB_BENCH_TEST` and run through direct `sqlcmd` via `run-libdb-bench-memory-optimized-tvp-optin.sql`. `verify-libdb-bench-test.sql` now treats the opt-in table/type/procedure as part of the final BENCH sync manifest. xUnit only checks script composition. | Recreate only `LIBDB_BENCH_TEST` for a clean slate; do not add memory-optimized teardown to the default benchmark reset. | Mitigated |
| AOT reflection fallback | Reflection-based object streaming can produce trim/AOT warnings or fail after publish. | Static-shape registration via `.Map<T>().Column(...)` is the documented AOT fast path. Public non-shape TVP overloads and JSON convenience APIs are annotated; local suppressions are limited to branches guarded by supplied static shapes. | Release gate: Native AOT publish must have zero Lib.Db-owned IL warnings and the published smoke executable must run against the local verification DB. | Mitigated |
| Provider AOT metadata | `Microsoft.Data.SqlClient` and transitive provider packages can emit provider-owned Native AOT warnings even when Lib.Db's static-shape path publishes and runs. | Native AOT publish is required on `win-x64`; warnings are classified by owning assembly instead of suppressed in Lib.Db. `docs/verification.md` tracks the warning policy. | Current observation: `Microsoft.Data.SqlClient` is pinned to `7.0.2`; `win-x64` publish produced only provider-owned warnings covered by `Verification/baselines/aot-warnings.json`. Release decision: accepted only if Lib.Db-owned warning count remains zero and provider warning IDs/packages match the baseline and release notes. | Accepted |
| Schema drift | DB TVP type changes can silently misbind rows or fail at runtime. | Default policy is `Strict`; descriptor + `TvpBindingPolicy.Adaptive` is limited to nullable/default-safe drift. Static shape records column order/type/size/precision/scale. | Keep integration coverage for incompatible drift and update descriptor docs when Worker B finalizes schema provider APIs. | Mitigated |
| Metadata visibility | SQL Server principals without metadata visibility may fail schema lookup or see incomplete TVP metadata. | Runtime binding can use explicit wrappers and registered shape; schema-adaptive descriptor lookup fails diagnostically instead of silently falling back. Benchmark DDL is isolated to `libdb_bench_*` objects. | Operations docs should grant only the minimum metadata visibility needed for schema-adaptive paths. | Open |
| Distributed flush | Cross-process epoch synchronization can invalidate broader schema cache than the originating targeted TVP flush. | Public `UseSchema(...).FlushTvpAsync(...)` routes through `ISchemaFlushCoordinator.FlushTvpAsync(...)`, and the originating process performs targeted local TVP cleanup for HybridCache, snapshot, negative cache, and descriptor row-accessor cache. Other processes currently observe an epoch change through the existing whole-schema sync path. | Keep epoch-store behavior covered in `SchemaFlushServiceTests`; do not document distributed targeted flush as fully narrow until the epoch payload carries TVP identity across processes. | Accepted |
| Permissions | TVP execution requires stored procedure execute permission and user-defined table type reference permission. | README and operations docs call out least-privilege TVP permissions; benchmark setup creates only known local `libdb_bench_*` objects through C# DDL. | Keep release reviews checking that TVP examples never suggest broad database roles or privileged SQL logins. | Mitigated |
