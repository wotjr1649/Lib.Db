# Lib.Db v2.3 Runtime TVP Design

## Goal

Lib.Db v2.3.0 removes the separate `Lib.Db.TvpGen` source-generator project and moves TVP support to a runtime-first pipeline inside the single `Lib.Db` package. The new design must handle both changing row values and database TVP type shape changes without requiring consumer source regeneration, while still preserving a benchmark baseline against the previous generated-accessor approach.

## Confirmed Direction

- Default API: `LibDb.Tvp("dbo.TypeName", rows)` returns an explicit runtime TVP value.
- Registered API: `services.AddLibDb(o => o.Tvp.Map<OrderItem>("dbo.T_OrderItem"))` enables repeat-use binding for a row type; this shape-discovery form is a JIT convenience path.
- AOT fast-path API: `services.AddLibDb(o => o.Tvp.Map<OrderItem>("dbo.T_OrderItem").Column(...))` registers the complete static column shape used by the official high-performance path.
- Auto TVP binding is enabled by default only for registered row types.
- Unregistered `IEnumerable<T>` values are not guessed as TVP values.
- Default schema drift policy is `Strict`.
- Optional schema drift policy is `Adaptive`.
- `LogOnly` is not a first-class production default because it can hide data integrity and security defects.
- v2.3.0 includes strong Native AOT support. The official high-performance path is a fluent static column-shape registration that avoids runtime property discovery and runtime code generation.
- Reflection-based object mapping is treated as a JIT convenience fallback, not the v2.3.0 AOT fast-path contract.
- A separate `Benchmarks/Lib.Db.Benchmarks` console project will run BenchmarkDotNet against a real SQL Server database.
- The benchmark project will keep a generated-accessor baseline as fixed benchmark-only code after `Lib.Db.TvpGen` is removed.

## Official Source Findings

- SQL Server TVPs are strongly typed user-defined table types, are passed by reference, and require `READONLY` in routines.
- TVP consumers need permissions to execute the routine and reference the user-defined table type or its schema.
- Microsoft.Data.SqlClient supports TVP values through `DataTable`, `DbDataReader`, and `IEnumerable<SqlDataRecord>`.
- TVP parameters must set `SqlParameter.SqlDbType = Structured` and a matching `SqlParameter.TypeName`.
- Native AOT library compatibility is validated through `IsAotCompatible`, trim/AOT analyzers, and publish-time checks.
- Libraries should avoid unbounded reflection and runtime code generation on AOT-supported public paths; remaining dynamic APIs should be explicitly annotated.
- Roslyn source generators react to compile inputs such as source, analyzer config, and additional files. They are not a runtime DB schema synchronization mechanism.
- BenchmarkDotNet supports explicit jobs, `MemoryDiagnoser`, Markdown and CSV exporters, and dedicated benchmark projects.

## Runtime TVP API

### Explicit Wrapper

```csharp
var rows = new[]
{
    new OrderItem(1, "A100", 2, 12.50m),
    new OrderItem(2, "B200", 1, 8.25m)
};

await db.Exec("dbo.SaveOrder", new
{
    OrderId = 123,
    RequestedBy = "system",
    Rows = LibDb.Tvp("dbo.T_OrderItem", rows)
});
```

The explicit wrapper has the highest binding priority. It always binds as `SqlDbType.Structured`.

### Registered Binding

```csharp
services.AddLibDb(o =>
{
    o.Tvp
        .Map<OrderItem>("dbo.T_OrderItem")
        .Column("Id", SqlDbType.Int, static x => x.Id)
        .Column("Sku", SqlDbType.NVarChar, static x => x.Sku, size: 64)
        .Column("Qty", SqlDbType.Int, static x => x.Qty)
        .Column("Price", SqlDbType.Decimal, static x => x.Price, precision: 18, scale: 2);
});

await db.Exec("dbo.SaveOrder", new
{
    OrderId = 123,
    RequestedBy = "system",
    Rows = orderItems
});
```

When `OrderItem` is registered, `IEnumerable<OrderItem>` binds as a TVP automatically. Registration is required to avoid confusing arbitrary enumerable values with TVP values.

For JIT-first applications, a shorter type-name-only registration remains available:

```csharp
services.AddLibDb(o => o.Tvp.Map<OrderItem>("dbo.T_OrderItem"));
```

That form may use reflection-based row shape discovery. It is not the official v2.3.0 AOT fast path.

### Mixed Parameters

A stored procedure call can combine scalar, TVP, output, return, and raw provider parameters.

```csharp
var resultCode = LibDb.Output<int>();

await db.Exec("dbo.SaveOrder", new
{
    OrderId = 123,
    RequestedBy = "system",
    Rows = LibDb.Tvp("dbo.T_OrderItem", orderItems),
    ResultCode = resultCode
});

int code = resultCode.Value;
```

Binding priority:

1. Existing `DbParameter` or `SqlParameter`
2. `LibDbTvpValue`
3. Registered `IEnumerable<T>` TVP
4. `LibDbOutput<T>` and return-value wrappers
5. Scalars
6. Unregistered enumerable values fail with an explanatory error

## Fluent API Fit Review

The chosen B+C model fits the existing Fluent API because it keeps stored procedure calls object-shaped and does not force a TVP-specific command path. The fluent surface remains about "execute this command with these parameters"; TVP becomes one parameter value type among scalar, output, and provider-native parameters.

Recommended fluent integration:

```csharp
await db.Exec("dbo.SaveOrder")
    .With(new
    {
        OrderId = 123,
        Rows = LibDb.Tvp("dbo.T_OrderItem", orderItems),
        RequestedBy = "system"
    })
    .ExecuteAsync();
```

Recommended object shorthand:

```csharp
await db.Exec("dbo.SaveOrder", new
{
    OrderId = 123,
    Rows = LibDb.Tvp("dbo.T_OrderItem", orderItems),
    RequestedBy = "system"
});
```

Recommended registered fast path:

```csharp
services.AddLibDb(o => o.Tvp
    .Map<OrderItem>("dbo.T_OrderItem")
    .Column("Id", SqlDbType.Int, static row => row.Id)
    .Column("Sku", SqlDbType.NVarChar, static row => row.Sku, size: 64)
    .Column("Qty", SqlDbType.Int, static row => row.Qty)
    .Column("Price", SqlDbType.Decimal, static row => row.Price, precision: 18, scale: 2));

await db.Exec("dbo.SaveOrder", new
{
    OrderId = 123,
    Rows = orderItems,
    RequestedBy = "system"
});
```

Design decision: do not add a separate `ExecTvp` or `WithTvpOnly` API. That would make mixed parameter calls worse and split the command model.

### Native AOT Fast Path

The v2.3.0 AOT contract is explicit and shape-first. A row type is AOT-safe when the application registers its TVP columns with static lambdas:

```csharp
services.AddLibDb(o => o.Tvp
    .Map<OrderItem>("dbo.T_OrderItem")
    .Column("Id", SqlDbType.Int, static x => x.Id)
    .Column("Sku", SqlDbType.NVarChar, static x => x.Sku, size: 64)
    .Column("Qty", SqlDbType.Int, static x => x.Qty)
    .Column("Price", SqlDbType.Decimal, static x => x.Price, precision: 18, scale: 2));
```

This path does not call `Type.GetProperties`, `Expression.Compile`, `MakeGenericMethod`, or `MethodInfo.Invoke` during TVP binding. It can build either a schema-aware `DbDataReader` or an `IEnumerable<SqlDataRecord>` writer from pre-registered column metadata and delegates.

The explicit wrapper can also accept a reusable shape object when dependency injection is not available:

```csharp
Rows = LibDb.Tvp("dbo.T_OrderItem", orderItems, OrderItemTvp.Shape)
```

Reflection-based object mapping remains available for local development and JIT-first applications, but it is annotated and documented as non-AOT fast path. It must not be required for the benchmarked v2.3 runtime path.

## Runtime Architecture

### Components

Implemented in the current v2.3.0 branch:

- `LibDbTvpValue`: immutable wrapper containing type name, row source, row shape hint, and policy override.
- `TvpTypeName`: validates and normalizes one-part or two-part SQL Server type names.
- `TvpOptions`: global runtime TVP settings.
- `TvpMappingRegistry`: maps CLR row type to SQL TVP type name and row accessor strategy.
- `TvpShape<T>` and `TvpShapeBuilder<T>`: AOT-safe pre-registered row shape containing SQL metadata and static value readers.
- `TvpMappingBuilder<T>`: fluent registration builder returned by `TvpOptions.Map<T>(...)`.
- `RuntimeTvpDataReader`: streaming `DbDataReader` over object rows, dictionaries, or already-shaped row sources.
- `SqlDataRecordTvpEnumerable`: high-performance AOT-safe writer over `IEnumerable<SqlDataRecord>` using `SqlMetaData`.
- `TvpBindingPolicy`: `Strict` by default, `Adaptive` optional.

Implemented v2.3 runtime components:

- `TvpSchemaProvider`: queries SQL Server catalog views for user-defined table type schema.
- `TvpSchemaFingerprint`: stable fingerprint over type name, column names, order, SQL types, length, precision, scale, and nullability.
- `TvpRowAccessorCache`: bounded cache for reflection fallback bindings keyed by row type and optional schema fingerprint.

Deferred optimization candidate:

- `TvpColumnWriter<T, TValue>`: typed column writer layer for later zero-boxing specialization if profiling proves it beats `SqlDataRecord`.

### Strict Policy

`Strict` throws when:

- an expected TVP column is missing from the row source
- a row property cannot be converted safely to the SQL type
- a non-nullable TVP column receives no value
- DB schema fingerprint differs from the cached binding in a way that changes required columns
- `typeName` fails validation

### Adaptive Policy

`Adaptive` allows:

- column name based reordering
- missing nullable columns as `DBNull.Value`
- missing columns with explicit configured defaults
- additional input columns being ignored when the DB TVP type does not define them

`Adaptive` still throws for type narrowing, non-nullable missing columns, unsupported SQL types, or invalid type names.

## Schema Drift Handling

Cold path:

1. Validate `typeName`.
2. Resolve DB TVP schema by name.
3. Build schema fingerprint.
4. Build row binding against schema.
5. Cache binding by `instanceHash + typeName + rowType + policy + schemaFingerprint`.

Warm path:

1. Use cached binding.
2. Send the AOT-safe `SqlDataRecord` writer when a registered static shape exists.
3. Otherwise send `RuntimeTvpDataReader` for explicit schema or JIT fallback scenarios.
4. On known schema-related SQL errors, invalidate the TVP binding and schema cache.

Manual refresh:

```csharp
await db.Schema.FlushTvpAsync("dbo.T_OrderItem", cancellationToken);
await db.UseSchema("Verification").FlushTvpAsync("dbo.T_OrderItem", cancellationToken);
```

This manual refresh API is part of the implemented v2.3 public surface. `IDbSession.Schema.FlushTvpAsync(...)` uses the current default execution instance, and `UseSchema(...).FlushTvpAsync(...)` routes through `ISchemaFlushCoordinator.FlushTvpAsync(...)` for an explicit instance. The local cleanup is targeted to the requested TVP type; cross-process epoch synchronization can still trigger broader schema refresh in other processes.

## Native AOT Acceptance Criteria

`Lib.Db` keeps `IsAotCompatible=true` on the library project to run compatibility analyzers during normal builds. `PublishAot=true` belongs to an executable smoke project, not the library project itself. The release gate passes only when the AOT-safe public surface is validated without broad assembly-level suppressions.

Required checks:

- Build `Lib.Db` with AOT, trim, and single-file analyzers enabled through `IsAotCompatible`.
- Add a small `Lib.Db.AotSmoke` console project that references the package/project and uses the fluent static TVP shape API.
- Publish the smoke app with `dotnet publish -c Release -r win-x64 /p:PublishAot=true`.
- Run the published smoke app against `LIBDB_VERIFICATION_TEST` and execute a stored procedure with scalar + TVP parameters.
- The `Lib.Db` official AOT path must not produce Lib.Db-owned IL2026, IL2070, IL2075, or IL3050 warnings.
- IL3058 reference-compatibility warnings are tracked separately as dependency/provider metadata risk, because a dependency can be AOT-usable before its package metadata declares `IsAotCompatible`.
- Any remaining non-AOT convenience APIs must be explicitly annotated with `RequiresUnreferencedCode` or `RequiresDynamicCode`, and must not be used by the smoke app.
- Remove broad AOT/trimming suppressions that hide runtime TVP warnings. Suppressions are allowed only when the invariant is local, documented, and covered by the AOT smoke test.

Provider risk:

- `Microsoft.Data.SqlClient` must be verified by actual publish-and-run testing, not by assumption. If provider-level AOT issues remain, v2.3.0 records them in a provider risk ledger with the warning id, package version, runtime identifier, observed behavior, and release decision.

## Security Review

This design was reviewed with Codex Security threat-modeling concerns.

### Assets

- SQL Server connection string and credentials
- stored procedure execution permission
- user-defined table type reference permission
- TVP row data, which can contain business-sensitive values
- schema metadata and diagnostics
- benchmark database objects created by the v2.3.0 benchmark project

### Trust Boundaries

- application code to Lib.Db binder
- Lib.Db binder to Microsoft.Data.SqlClient
- SQL Server catalog metadata queries
- benchmark/test DDL execution
- configuration and logging sinks

### Attacker-Controlled Inputs

- stored procedure names when applications pass dynamic command names
- TVP type names when applications pass dynamic type names
- row values
- row dictionaries and column names
- configuration values controlling schema drift policy

### Required Guardrails

- `typeName` must never be interpolated into executable SQL text.
- `typeName` must be validated before assignment to `SqlParameter.TypeName`.
- Runtime schema lookup SQL must use parameters for schema and type name filters.
- Logs must not include connection strings, secrets, or row values.
- Diagnostics may include type name, column count, schema fingerprint, and policy name.
- Benchmark DDL must be isolated to configured local/direct SQL Server test databases.
- Direct SQL execution outside application/test paths must follow the user's approval rule. For this v2.3.0 work, the user explicitly allowed benchmark/test DDL for tables, TVP types, and stored procedures.

### Security Acceptance Criteria

- Invalid TVP names such as `dbo.X; DROP TABLE T` fail before any SQL command is executed.
- Dynamic schema queries are parameterized.
- Schema drift exceptions redact row values.
- Connection string values are never printed by tests, benchmarks, or diagnostics.
- Benchmark setup can drop and recreate only known `libdb_bench_*` objects.
- `Adaptive` policy cannot silently drop required values.

## Benchmark Design

Project: `Benchmarks/Lib.Db.Benchmarks`

Current benchmark dimensions:

- row counts: `100`, `1_000`, `10_000` by default; `100_000` when `LIBDB_BENCHMARK_SCALE=Full`
- column shapes: narrow 4-column TVP and wide 16-column TVP
- comparison groups: `GeneratedAccessorBaseline`, `RuntimeObjectStreaming`, `RuntimeRegisteredFastPath`
- runtime fast-path: registered static shape + `IEnumerable<SqlDataRecord>`

Planned benchmark dimensions:

- row counts: `100`, `1_000`, `10_000`, `100_000`
- column shapes: narrow, medium, wide
- policy: `Strict`, `Adaptive`
- cache state: cold schema, warm schema

Planned comparison groups:

- `DataTableBaseline`
- `GeneratedAccessorBaseline`
- `RuntimeObjectStreaming`
- `RuntimeDictionaryStreaming`
- `RuntimeSchemaAdaptive`
- `SqlDataRecordStreaming`

Generated baseline preservation:

- `Lib.Db.TvpGen` project is removed from the solution and package.
- Benchmark project contains fixed baseline code that mirrors the v2.2.1 generated accessor pattern.
- Baseline code is isolated under `Benchmarks/Lib.Db.Benchmarks/Baselines`.
- Production code does not depend on Roslyn generator output.

Benchmark outputs:

- BenchmarkDotNet Markdown report
- CSV measurements
- memory allocation report
- environment summary

Current ShortRun observation on 2026-05-17 against `LIBDB_VERIFICATION_TEST`:

- `RuntimeRegisteredFastPath` now uses registered static shape + `IEnumerable<SqlDataRecord>`.
- Allocated memory dropped versus generated baseline to about `0.04x` at 100 rows, `0.02x` at 1,000 rows, and `0.02x` at 10,000 rows in the ShortRun report.
- Mean timings were competitive in the same ShortRun (`8.282 ms`, `34.060 ms`, `88.649 ms` for 100/1,000/10,000 rows), but N=3 variance is high, so timing superiority requires a longer run before release claims.

Completion evidence to keep with the v2.3.0 release checklist:

- Descriptor-driven runtime TVP binding is documented through `TvpShape.For<T>().Column(...).Build()` plus `LibDb.Tvp(..., shape, TvpBindingPolicy.Adaptive)`.
- Static-shape AOT fast path is documented through `.Map<T>(...).Column(...)` registration and the registered enumerable TVP binding path.
- Targeted TVP flush is implemented through `IDbSession.Schema.FlushTvpAsync(...)` and `UseSchema(...).FlushTvpAsync(...)`; release notes must describe local targeted cleanup and the broader cross-process epoch behavior separately.
- Generated accessor baseline is preserved as `[Benchmark(Baseline = true)]` for both narrow and wide benchmark classes.
- Runtime benchmarks compare `RuntimeObjectStreaming` and `RuntimeRegisteredFastPath` against that generated baseline.
- The benchmark matrix includes narrow/wide TVP shapes and the default `100`/`1_000`/`10_000` rows, with `100_000` gated by `LIBDB_BENCHMARK_SCALE=Full`.

## Migration Notes

Before:

```csharp
[TvpRow(TypeName = "dbo.T_OrderItem")]
public sealed record OrderItem(...);
```

After explicit:

```csharp
Rows = LibDb.Tvp("dbo.T_OrderItem", orderItems)
```

After registered:

```csharp
services.AddLibDb(o => o.Tvp
    .Map<OrderItem>("dbo.T_OrderItem")
    .Column("Id", SqlDbType.Int, static x => x.Id)
    .Column("Sku", SqlDbType.NVarChar, static x => x.Sku, size: 64)
    .Column("Qty", SqlDbType.Int, static x => x.Qty)
    .Column("Price", SqlDbType.Decimal, static x => x.Price, precision: 18, scale: 2));
Rows = orderItems
```

`Lib.Db.TvpGen` attributes remain as obsolete compatibility markers only if removing them would create excessive migration pain. The preferred v2.3.0 target is no source-generator dependency.

## Open Implementation Constraints

- The benchmark project may temporarily reference or copy v2.2.1 generated baseline logic, but the final production package must not include `Lib.Db.TvpGen`.
- The official AOT path must not depend on `Expression.Compile`, `MakeGenericMethod`, `MethodInfo.Invoke`, or runtime property discovery.
- Reflection-based mapping can remain only as a clearly annotated JIT convenience fallback.
- `GlobalSuppressions.cs` must be narrowed so runtime TVP AOT warnings are not hidden from the smoke project.
- The library project must not set `PublishAot`; NativeAOT publish belongs to `Lib.Db.AotSmoke` and benchmark/smoke executable validation.
