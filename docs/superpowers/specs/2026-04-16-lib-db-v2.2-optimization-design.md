# Lib.Db v2.2 최적화 설계 사양서

> 작성일: 2026-04-16
> 대상: Lib.Db v2.1.0 → v2.2.0 (Breaking Change 허용)
> 범위: Lib.Db (71개 소스) + Lib.Db.TvpGen (7개 소스) 전체 수정

## 1. 배경 및 목적

Lib.Db v2.1.0의 심층 코드 리뷰 결과 **Critical 10건, Major 29건, Minor 30건**의 이슈가 식별되었다.
v2.2.0에서 이를 전부 해결하여 다음 목표를 달성한다:

- **정확성**: TvpGen 생성 코드의 Nullable/타입 매핑 버그 수정
- **안정성**: 메모리 누수, thread safety, DI 안티패턴 해결
- **유지보수성**: 코드 중복 제거, public API surface 정리
- **성능**: hot path zero-allocation, BulkInsert Reflection 제거
- **문서 품질**: 모든 public API Korean XML doc 완비

## 2. Breaking Changes 목록

v2.2.0은 Minor→Major 수준의 API 변경을 포함한다:

| 변경 | 영향 | 마이그레이션 |
|---|---|---|
| `EnableOpenTelemetry` → `[Obsolete]`, `EnableObservability`로 단일화 | 설정 코드 수정 필요 | `EnableOpenTelemetry` → `EnableObservability`로 변경 |
| `AdaptivePolicyFactory` 제거 또는 DI 등록 변경 | 직접 사용자 (거의 없음) | `DefaultResiliencePipelineProvider` 사용 |
| `TvpGenFeatureTokens` public → internal | TvpGen 어셈블리 직접 참조자 (거의 없음) | 제거 — 직접 참조 불가 |
| `ThrottledDbHealthCheck` 동작 변경 (static→instance 상태) | 동작 차이 없음 (내부 구현) | 변경 없음 |
| `TypeMappingRegistry` date/time 매핑 변경 | `[GenerateTvpFromDb]` 사용 시 생성 코드 타입 변경 | `DateTime` → `DateOnly`, `TimeSpan` → `TimeOnly` 확인 |
| `LibDbOptions.Mars` 속성 추가 (신규) | 기본값 `Auto` — 기존 동작과 호환 | 기존 코드 변경 불필요. `ForceEnable` 사용 시 ConnectionString 자동 보정 |

## 4. 실행 순서 및 의존성

```
Track 1 (TvpGen)  ──→  Track 3 (중복/아키텍처) ──→  Track 5 (주석/표준화)
                           ↑
Track 2 (메모리/안전) ──→  Track 4 (성능) ──→  Track 6 (MARS 정책)
```

- Track 1과 Track 2는 병렬 실행 가능 (TvpGen과 Lib.Db 소스가 분리됨)
- Track 3은 Track 1/2의 수정 결과에 의존 (중복 제거 시 수정된 파일 기준)
- Track 4는 Track 2의 안전성 수정 후 진행 (성능 최적화 전 메모리 안전 확보)
- Track 5는 모든 Track 완료 후 마지막 (주석은 최종 코드에 추가)
- Track 6은 Track 4 이후 (s_marsEnabledCache 수정 반영, ValidateMarsEnabled 리팩토링 기반)
